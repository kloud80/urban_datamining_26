초기 멀티모달

이미지를 텍스트로 번역해서 넣어 주면 알아서 해석하겠지 — 그게 최초의 발상이었다.

OCR

별도의
전문 영역이었다

MNIST 를 해 봤으면 안다 — 사람이 봐도 애매한 글자가 있다.

언어도 여럿, 글씨체도 여럿. 국내에도 OCR 을 강점으로 성장한 회사들이 있다 — 금융·행정 문서의 디지털화가 그 시장이었다.
CLIP

이미지와 텍스트를
같은 공간으로

인터넷의 이미지 + 캡션 을 긁어 4억 쌍. 파일이 아니라 URL 과 캡션을 배포했다.

대각선만 크게 만든다

Loss 를 어떻게 설계하느냐의 문제

짝인 것끼리 벡터가 같으면 곱했을 때 대각선이 제일 커진다 — 그렇게 되도록 밀어붙인다.

프로젝트가 남긴 것

인코더 두 개의 가중치

이것만 있으면 어떤 이미지든 텍스트와 같은 공간의 벡터로 바꿀 수 있다.

후보를 주고 고르게 한다

32 VLM.ipynb

주의 — 이미지를 넣으면 문장이 나오는 게 아니다. 후보를 내가 줘야 하고, 그중에서 고를 뿐이다.

한계

한 번 건너가야 한다

게다가 CLIP 의 임베딩과 LLM 의 임베딩은 서로 다른 물건이다 — 그냥 이어 붙일 수 없다.

이미지를 토큰으로 본다

Vision Transformer · 2020

순서대로 넣는 것 같지만 무차별로 넣고 위치 정보를 붙인다 — 언어의 포지셔널 인코딩과 같다.

멀리 떨어진 것끼리 손을 든다

CNN 과의 결정적 차이

CNN 에서는 마지막 층까지 가야 둘이 만난다. ViT 에서는 처음부터 만난다.

초기 ViT 의 벽

4 억 장은
너무 적다

언어는

마스킹으로 무한히 데이터를 만들었다 — 인터넷 전체가 학습 데이터였다.

이미지는

쌍이 있어야 했고, 학습해 봐야 나오는 건 캡션뿐이었다.

“그놈이 그놈이네, 차라리 CNN 이 낫다” — 초기 ViT 의 평가였다.

MAE · 2021

가리고 복원시켰더니

언어에서 단어를 가리고 맞히던 것과 정확히 같은 발상 — 라벨이 필요 없다.

뜻하지 않은 결과

글자 인식기가 그냥 생겼다

“여기 이 글자가 나와야 글자가 완성될 것 같은데” 로 복원하다 보니 —
지금 우리가 PDF 를 그냥 던지는 이유가 이것이다.

아예 한 모델 안으로

VLM — Vision Language Model

이제 이미지 패치와 텍스트 토큰이 서로 어텐션한다. 건너갈 필요가 없어졌다.

우리 분야에 직접 닿는 대목

표와
숨은 글자

OCR 이 끝내 못 하던 것 — 표, 그리고 지도·범례 안의 글자.

글자는 읽어도 어디에 붙어 있었는지를 몰랐다.

행정 문서의 표를 떠올려 보라 — 칸을 치고 없애고 합친다. 사람에겐 좋고 OCR 에겐 지옥이었다.

서로 어텐션이 되니 “이 텍스트는 이 칸의 것” 까지 연결된다.

DiT · Diffusion Transformer

U-Net 자리에 트랜스포머를 넣었다

왼손이 여기 있으면 그 맥락으로 오른손을 그린다 — 예전 디퓨전이 손가락을 못 그리던 이유가 이걸로 풀렸다.

영상은 한 판의 이미지다

프레임을 전부 붙여서 패치로

첫 장면과 끝 장면 사이를 트랜스포머가 이어 준다 — 어마어마한 계산량인데도 지금 돌아가고 있다.

판을 바꾼 것은 둘뿐이다
Transformer

멀리 있는 것끼리 직접 손을 든다

언어 → 이미지(ViT) → 생성(DiT) → 영상

Masked Learning

가리고 맞히면 라벨이 필요 없다

언어 → 이미지(MAE) → 표 데이터의 빈칸까지

이 두 단어만 붙들고 있으면 앞으로 나올 것들도 읽힌다.

속도에 대하여

여기까지 오는 데 몇 년이 걸렸나

연구에 한계를 미리 긋지 말 것. 다만 학위를 마칠 때쯤 시장은 또 바뀌어 있다 — 그 속도감을 안고 공부할 것.

2교시 정리
  1. CLIP — 이미지와 텍스트를 같은 벡터 공간으로 끌어왔다.
  2. ViT — 이미지를 16×16 토큰으로 보니 멀리 있는 것끼리 만난다.
  3. MAE — 가리고 복원하니 라벨 없이 학습된다. OCR 이 사라졌다.
  4. VLM · DiT — 아예 한 모델 안에서 이미지와 글이 서로 어텐션한다.
우리 분야에 가장 큰 변화 — 표와 지도 속 글자를 읽을 수 있게 됐다.
